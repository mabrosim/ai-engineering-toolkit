# Markdown Quality Rules

Semantic quality criteria for Markdown in this repository. Repository-local
tooling owns mechanical pass/fail rules.

---

## Accuracy

- Match behavioral and technical claims to current source evidence
- Keep commands, examples, names, and paths valid and internally consistent
- State material assumptions, requirements, and limitations

---

## Organization

- Organize sections around the reader's task and dependency order
- Use headings that identify and distinguish their content
- Keep each section relevant to the document's stated purpose

---

## Links

- Use descriptive link text
- Verify link targets before finalizing
- Use relative paths for internal repository links

---

## Presentation

- Choose lists, tables, examples, or diagrams according to the information
 being communicated
- Keep tables scannable and explain non-obvious labels
- Remove stale, duplicated, or source-restating content
